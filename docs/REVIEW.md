# Review: make investigations ready for real playtests

CaseZero's remaining friction was concentrated in long investigations and recovery: save failures were easy to miss, malformed live updates could discard a good session, thread shortcuts skipped explanation choices, and mobile players repeatedly scrolled between records and reasoning. Phase 5 preserves all three stories, proof paths and save formats while making those interactions explicit and recoverable.

Files now pin directly to the board. Thread controls remove hidden pins, reset filters and include explanations at their destination. Timeline shortcuts retain drafts and show full selected events on small screens. Native dialog isolation, touch targets, 16px inputs, stable labels and visible dismissal support keyboard and mobile use. Save retry preserves the latest snapshot, including reset intent, and import has clear pending/retry/focus behavior.

Local playtest feedback produces reviewed copy/download reports with a safe context allowlist, no automatic submission and no notebook/clue/accusation disclosure. Clipboard denial exposes a selectable fallback. A production error boundary reloads the last browser save after a failed ending file. Node 24.x and repository exclusions support a standard Next.js host without new dependencies or required configuration.

[DEPLOYMENT.md](DEPLOYMENT.md) explains the phone-only GitHub/Vercel/Safari handoff and its separate publication approval. [PLAYTESTING.md](PLAYTESTING.md) includes a practical manual checklist and human feedback prompts. No external repository, push or deployment was performed, and no human/device results are claimed.

Validation passed: typecheck, lint, production build/start, clean install, all 126 unit/component tests and all 148 production browser tests (37 each in Firefox, WebKit, desktop Chromium and mobile Chromium emulation). Audited states have zero axe violations. Exact test scope, fault injection, browser setup and limits are in [VERIFICATION.md](VERIFICATION.md); milestone evidence is in [PLAN.md](PLAN.md). The next priority is first-time human sessions and actual phone/VoiceOver testing, followed by focused difficulty/hint tuning based on repeated observations.
